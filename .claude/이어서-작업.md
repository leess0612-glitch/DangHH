### 스타일이 어디에 있나 (중요)

같은 머리띠·발바닥이 **다섯 벌로 복사**돼 있습니다. 한 줄 고치려면 다섯 곳을 고쳐야 합니다.

| 출처 | 적용 장수 |
|---|---|
| `index.html` 인라인 `<style>` | 1 |
| `rental.html` · `rental-c.html` 인라인 | 2 |
| `gift.html` 인라인 | 1 |
| `privacy.html` · `terms.html` · `appliance/index.html` 인라인 | 3 |
| `css/dh-plans.css` | 11 (요금표 6 + 셋톱 5) |
| `css/dh-brand.css` | 400 (정수기 water/ 200 + water-c/ 200) |

발바닥 **글과 마크업**은 이미 `js/dh-footer.js` 한 곳으로 모여 있습니다 — 그래서 문구는 처음부터 421장이 같았습니다. 머리띠 아래 폰 메뉴 줄은 `js/dh-topnav.js` 입니다.

`css/*.css` 를 고치면 **부르는 쪽 주소의 `?v=` 번호를 올려야** 손님 화면에 반영됩니다.
현재: `dh-brand.css?v=70` (400장) · `dh-plans.css?v=15` (11장).

## 일부러 남겨 둔 것 (사장님 판단 필요)

### 1. 정수기 띠 단추 글자 20px
`css/dh-bar3.css` 의 `.bar-cta` 가 `--t-h2`(20px), 480px 이하에서는 `--t-h3`(16px).
→ **실제 폰에서는 이미 16px 이라 다른 화면과 같습니다.** 20px 은 481px 이상에서만 보입니다.
정수기 상세는 단추 위에 요금 세 줄이 얹힌 한 세트라 크기 차이에 근거가 있습니다.
400장의 신청 단추 크기는 디자인이 아니라 **전환율** 문제라 손대지 않았습니다.

### 2. 본문 자간
`css/dh-brand.css` 만 `body { letter-spacing: -.01em }` 이고 나머지 21장은 `normal`.
그래서 메뉴 폭이 **682(21장) vs 676(정수기 400장)** 으로 6px 다릅니다.
맞추려면 21장의 **모든 글줄**이 미세하게 움직이므로 따로 잡아야 합니다.

## 남은 큰 일 — 근본 해결 (아직 시작 안 함)

이번에 고친 여덟 가지가 **전부 위 "다섯 벌 복사본" 사이의 어긋남**이었습니다.
복사본이 남아 있는 한 같은 문제가 또 생깁니다. 공용 CSS 한 벌로 합치는 작업입니다.

### 목표 모습

```
css/dh-shell.css    ← 새로 만듦. 머리띠·발바닥·하단띠·로고·토큰 한 벌
  ├─ 421장이 <link> 한 줄로 부름
  ├─ dh-brand.css → 정수기 본문 전용만 남김
  ├─ dh-plans.css → 요금표 본문 전용만 남김
  └─ 인라인 7장   → 머리띠·발바닥 덩어리 삭제, 본문 스타일만 남김
```

### 단계 (단계마다 따로 커밋)

| 단계 | 할 일 | 파일 수 | 위험 |
|---:|---|---:|---|
| **0** | **안전망 먼저** — 421장 × 6폭을 찍어 기준 스샷으로 저장하는 스크립트를 repo 에 넣음 | +1 | 없음 |
| 1 | `dh-shell.css` 작성 — `dh-brand.css` 의 머리띠·발바닥·띠·토큰을 **값 변경 없이** 옮겨 적음 | +1 | 없음 |
| 2 | 정수기 400장이 `dh-shell.css` 를 부르게 하고 `dh-brand.css` 에서 겹치는 덩어리 삭제 | 401 | 낮음 |
| 3 | 요금표·셋톱 11장 같은 방식 | 12 | 중 |
| 4 | 인라인 7장 같은 방식 | 7 | **높음** |
| 5 | 0단계 스샷과 대조 → 달라진 곳만 검토 | — | — |

**0~2단계까지만 먼저 하는 것을 권합니다.** 정수기 400장은 이미 `dh-brand.css` 한 곳에서
관리되고 있어 사실상 이름만 바꾸는 수준이라 위험이 거의 없고, 그것만으로도
"공용 파일이 존재한다"는 발판이 생깁니다. 3·4단계는 나중에 하나씩 옮기면 됩니다.

## 확인하는 방법 (실제로 재는 법)

눈으로 보지 말고 **헤드리스 크로미움으로 재서** 확인했습니다. 같은 방법을 쓰세요.

```bash
# 1) 사이트를 로컬에 띄운다 (저장소 최상위에서)
python3 -m http.server 8777

# 2) 다른 창에서 playwright 로 잰다
pip install playwright        # 처음 한 번
```

재는 항목 예시 — 한 쪽을 열고 `getComputedStyle` 로 뽑습니다:

- 머리띠: `header nav a` 의 `fontSize` · `fontWeight` · `color` · `paddingLeft` · 높이
- 로고: `header .logo` 의 `gap` · 마크와 글자 사이 실측(`getBoundingClientRect`)
- 발바닥: `footer` 의 `backgroundColor` · `fontWeight`, `.footer-disclaimer` 의 `fontWeight`
- 하단띠: `.mobile-cta-bar` 높이 · `.mobile-cta-btn` 의 크기·굵기·모서리
- 넘침: `documentElement.scrollWidth > clientWidth`, 그리고
  `머리띠 안쪽폭 - (로고폭 + 메뉴폭)` 이 음수인지

**꼭 봐야 하는 창 폭**: 375 · 768 · **769** · 880 · **881** · 931 · 1200
(769 와 881 이 규칙이 갈리는 경계라 여기서 깨집니다)

⚠️ 이 환경에는 Pretendard 글꼴이 없어 대체 글꼴로 재집니다. 대체 글꼴이 더 넓으므로
**실제 화면은 잰 값보다 여유가 있습니다** — 즉 이 방식은 안전한 쪽으로 틀립니다.

## 하면 안 되는 것 · 주의

- **`--gray` · `--w-sub` · `--w-min` 같은 눈금 자체를 바꾸지 말 것.**
  여러 곳이 같이 쓰고 있습니다. 머리띠·발바닥만 고칠 때는 그 규칙에 값을 직접 적으세요.
  (실제로 이번에 `nav a` · `footer` 규칙에 값을 직접 박는 방식으로 처리했습니다)
- **`css/*.css` 를 고치면 `?v=` 올리는 것을 잊지 말 것.** 안 올리면 손님 화면이 안 바뀝니다.
- **하단 신청띠의 단추 태그**는 동작에 따라 다릅니다 — 신청창을 여는 것은 `<button type="button">`,
  다른 화면으로 가는 것(privacy·terms·appliance)은 `<a href="...index.html#apply-now">`.
  `#apply-now` 는 첫 화면이 알아듣는 신호라서 신청창이 바로 뜹니다. 바꾸지 마세요.
- **`data/휴무일.json`** 은 자동 백업이 매일 건드립니다. 충돌 나면 `main` 쪽을 쓰세요.
- 이 저장소는 **GitHub Pages 로 `main` 을 그대로 띄웁니다.** `main` 에 들어가는 순간 라이브입니다.
  확인 없이 `main` 에 직접 밀지 말고 PR 로 올리세요.
